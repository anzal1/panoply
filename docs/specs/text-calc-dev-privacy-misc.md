# Module specs: Text and clipboard (11), Calculators (12), Developer tools (13), Privacy and security (14), Business paperwork (15), Print (16), Your computer (17), plus network and model policy

Template and shared capabilities: see FLOWS.md. Each spec lists only what is
special to the module. Fields that would only repeat the host (Preview,
Output, Result card, "originals untouched") are omitted when the pattern makes
them obvious.

## Conventions used in this file

- **Pattern F answers.** Unless a spec says otherwise, Return copies the bare
  answer (no thousands separators, unit kept: `12000 s`), Option+Return copies
  `expression = answer`, Tab opens the panel with the full breakdown. Typed
  input only activates a module when it matches the module's trigger grammar,
  so the bar never fills with noise. A module that is not sure stays silent.
- **Trigger grammar** is written as patterns. `<text>` is free text, `[x]` is
  optional, `a|b` is a choice. Triggers are case-insensitive and tolerate
  extra spaces.
- **Sensitive modules.** Anything that handles secrets (passwords, JWTs, keys,
  health numbers, breach checks) opts out of the host History capability by
  default and says so in its Privacy line. A secret never appears in History,
  in logs, or in an MCP response unless the module says so.
- **Budgets.** Every spec ends with a `Budgets:` line. The table in FLOWS.md
  ("Budgets every module must meet": 0% idle CPU, no memory held when idle,
  start under 50 ms, first preview under 100 ms, no UI-thread task over 4 ms,
  120 fps, 300 MB peak per job, models unload after 60 s idle) applies to all
  of them. The line states only what is special: an exception, a tighter
  number, or what the always-on parts cost. Budgets are targets that CI
  measures, not measured results. Competitor comparisons are run by us on a published corpus;
  no comparison result is claimed until it is run.
- **Feasibility marks** in section 17: **Y** public API, no special
  permission. **P** public API behind a user permission. **X** needs a private
  or undocumented API, or a privileged helper. **N** impossible on that OS.
- **CLI naming.** `panoply <group> <verb>`. ID photos already own
  `panoply id`, so generated identifiers use `panoply gen`. MCP tool names are
  `group_verb` in snake case.
- **MCP safety.** Read tools that expose personal history (clipboard, scratchpad,
  snippets) are off by default and need a per-session approval. Write tools
  that change files or system state default to dry run.

# 11. Text and clipboard

## 11.1 Clipboard history

- **Pattern:** G, always on. **Job:** "Paste something I copied earlier, without hunting for it."
- **Stored:** text (plain plus rich as a lazy second flavor), images, file
  references (paths, not contents), colors. Each item keeps source app, time,
  type, a content hash for dedupe, and the pasteboard types it arrived with.
  Nothing else. Stored in one SQLite database in the app data folder, encrypted
  at rest with SQLCipher-class whole-file encryption. The key lives in the OS
  keystore (Keychain, DPAPI, Secret Service, Android Keystore), never in a file.
  Image blobs are separate files encrypted with the same key. Search uses an
  FTS5 index stored inside the encrypted database, so no plaintext index
  touches disk and none is held in memory.
- **Retention:** defaults are 1,000 items or 30 days, whichever hits first;
  image total capped at 200 MB; pinned items never expire. All editable.
  "Clear all" and "Clear last 5 minutes" are one keystroke and really delete
  (VACUUM plus blob unlink).
- **Secrets are skipped, not stored then hidden.** An item is dropped before it
  is written if: the pasteboard carries `org.nspasteboard.ConcealedType`,
  `org.nspasteboard.TransientType` or `org.nspasteboard.AutoGeneratedType`
  (nspasteboard.org convention, used by 1Password, Bitwarden, KeePassXC and
  others); on Windows the clipboard carries `ExcludeClipboardContentFromMonitorProcessing`
  or `CanIncludeInClipboardHistory` set to 0; on KDE the MIME type
  `x-kde-passwordManagerHint` is `secret`; or the source app is on the exclude
  list (default: Keychain Access, 1Password, Bitwarden, KeePassXC, Dashlane,
  Proton Pass, LastPass). Second line of defence: a text item that looks like a
  secret (known token prefixes such as `ghp_`, `sk-`, `AKIA`, PEM private key
  headers, Luhn-valid card numbers, JWTs, long high-entropy single tokens) is
  kept in memory only for 2 minutes, never written to disk, unless pinned.
  Panoply's own Passwords module marks its copies concealed.
- **Capture:** macOS has no change event, so poll `NSPasteboard.changeCount`
  every 250 ms (a single integer read). Windows uses `AddClipboardFormatListener`
  (event driven). Linux X11 uses XFixes selection events; Wayland needs
  `wlr-data-control` or `ext-data-control` (GNOME does not offer it, so GNOME
  needs a small shell extension). Phones: iOS cannot read the clipboard in the
  background and prompts on paste, Android 10+ blocks background reads, so on
  phones history fills only while Panoply or its keyboard is in front. State
  this in the app, do not hide it. macOS has started gating programmatic
  pasteboard reads behind a user setting (API added in 15.4); handle "denied"
  with a one-screen fix, not silence.
- **Options:** paste as plain text (Shift+Return), sequential paste (queue),
  merge selected items, retention, exclude apps, ignore image copies.
- **Edge cases:** 200 MB single copy (store a reference and a thumbnail, never
  the blob in memory); copy from a virtual machine or remote desktop firing
  changes many times a second (debounce 150 ms); the same item copied twice
  (move to top, no duplicate); copy that disappears (promised data never
  delivered) skipped; clipboard written by Panoply itself ignored.
- **Quality bar:** zero secrets stored in a test suite that replays real
  password manager copy events from 1Password, Bitwarden, KeePassXC, and Chrome
  and Safari password autofill. Beat Maccy on search (fuzzy, OCR text in
  images) and on secret handling (Maccy relies on the ignore list and the
  concealed type), Raycast and Alfred on being free and encrypted, and
  Windows Win+V on item count and search.
- **Engine:** Rust core, `rusqlite` with SQLCipher, OS pasteboard bindings.
- **Surfaces:** global shortcut panel, bar. CLI `panoply clip list|search|get|pin|clear`.
  MCP `clipboard_search` (off by default, never returns pinned secrets or
  flagged items), `clipboard_copy`.
- **Budgets:** The one module that cannot reach 0% idle on macOS (no change
  event exists), so the exception is explicit. macOS polls `changeCount` at
  250 ms only while the session is active and unlocked, drops to 1 s after 60
  s without a change, stops when the screen locks or the Mac sleeps, and sets
  100 ms timer leeway so wake-ups coalesce with other work. Windows, X11 and
  Wayland are event driven: zero wake-ups. Resident memory under 20 MB at
  10,000 items: no in-memory copy of history, rows and thumbnails loaded on
  demand, a copied blob is written to disk and released immediately. Panel
  opens under 50 ms, search under 30 ms on 10,000 items, image decoding off
  the UI thread.

## 11.2 Clean links

- **Pattern:** G, always on. **Job:** "Strip the tracking junk from links I copy."
- **Trigger:** a clipboard change whose entire text is one URL. Text with a URL
  inside a sentence is left alone. Modes: Auto (rewrite and toast "Cleaned 3
  parameters, Undo"), Ask, Off. Default Auto for URLs, Undo is Command+Z in the toast.
- **Removes:** `utm_*`, `fbclid`, `gclid`, `dclid`, `msclkid`, `yclid`,
  `twclid`, `ttclid`, `igshid`, `mc_eid`, `mkt_tok`, `_hsenc`, `_hsmi`,
  `li_fat_id`, YouTube and Spotify `si`, Twitter `s` and `t` on status links,
  Amazon `ref`, `tag`, `pd_rd_*` (reduces to `/dp/ASIN`). Unwraps redirectors
  offline when the target is in the URL (`google.com/url?q=`,
  `l.facebook.com/l.php?u=`, `out.reddit`, newsletter wrappers).
- **Never removes** parameters a site needs: `v`, `list`, `t` on YouTube
  watch links, `q`, `id`, `page`, signed-URL params (`X-Amz-*`, `sig`, `token`).
  Rules are per host with a global fallback, as data in a versioned file.
- **Edge cases:** `t.co` and `bit.ly` cannot be unwrapped offline (left alone,
  the toast says so); fragment `#` kept; internationalized domains; URLs with
  encoded parameters; `mailto:` and `tel:` untouched; localhost URLs untouched.
- **Quality bar:** on a corpus of 500 copied links from news, shopping, social
  and email the cleaned link still loads the same page (checked by a one-time
  script, not at runtime), and no needed parameter is removed. Ruleset is
  ClearURLs-compatible so it can import theirs (their data is LGPL: check
  before bundling, otherwise write our own). Beat browser "copy clean link"
  features by working in every app.
- **Engine:** Rust `url` crate plus rule file. **Surfaces:** toast, bar
  (`clean <url>`), CLI `panoply link clean <url>`, MCP `link_clean`.
- **Budgets:** Rides on 11.1's watcher, so adds zero wake-ups and no resident
  memory beyond the rule table (under 1 MB, parsed once per change). Rewrite
  finishes under 5 ms so the toast never lags the paste.

## 11.3 Redact pasted text

- **Pattern:** I, with fix on Return. **Job:** "Hide my emails, phones and IDs before I paste this into a chatbot or a ticket."
- **Inputs:** clipboard text or selection. A hotkey runs it on whatever is
  copied, shows detections highlighted, Return replaces the clipboard with the
  redacted text.
- **Detects:** email, phone (E.164 and Indian 10-digit), Aadhaar (12 digits,
  Verhoeff check, first digit 2 to 9), PAN (`AAAAA9999A`), GSTIN (checksum),
  card numbers (Luhn), IBAN (mod 97), SSN-shaped, IP addresses, URLs with
  tokens, API keys by prefix, JWTs, plus names and addresses from a small
  on-device token-classification model (ONNX, 🧠, budget under 100 MB, runs
  only when the Names toggle is on). Regex hits with a checksum are high
  confidence and pre-checked; model hits are pre-checked above a threshold the
  user can move.
- **Options:** style (`[EMAIL_1]` placeholders, black blocks, mask last 4,
  realistic fake values), keep-mapping (default on).
- **Round trip:** with placeholders, the mapping stays on the device. Paste the
  chatbot's answer back and "Restore" swaps `[EMAIL_1]` back to the original.
  The mapping is held in memory for 1 hour, then discarded, never stored.
- **Edge cases:** the same value in several formats (`+91 98765 43210`,
  `9876543210`) gets one placeholder; text with line breaks inside numbers;
  names that are also words; non-Latin scripts (Devanagari names are model
  work, say so when the model is off); overlapping detections (longest wins).
- **Quality bar:** recall is measured per category on a labelled synthetic
  corpus and published; default threshold favors recall because the user
  reviews. Aadhaar, PAN, GSTIN, card, IBAN, email detection is deterministic and
  must hit 100% of valid-format test values with zero false positives on a
  corpus of ordinary prose. Beat Microsoft Presidio's regex recognizers on
  Indian IDs (it has few) and a manual find-and-replace on speed.
- **Engine:** OS first, own model second. Names, places and organizations: macOS
  and iOS use Apple NaturalLanguage `NLTagger` (people, places, organizations).
  Android uses ML Kit Entity Extraction (structured entities such as dates and
  addresses, not person names). Windows: none found. Linux: none. Fallback model
  (any platform where the OS engine is absent or fails the quality bar test in
  CI, and for any category the OS engine does not return, such as person names
  on Android): the small names model (ONNX Runtime, token classification) plus
  the regex and checksum validators. The regex and checksum validators run on
  every platform and are never replaced by an OS engine. Rust regex plus
  checksums stay the engine for all structured IDs.
- **Surfaces:** hotkey, bar, CLI `panoply redact text`, MCP `redact_text`
  (returns redacted text only, the mapping never leaves the device).
- **Budgets:** Regex and checksum path under 20 ms for 100 KB of text and
  needs no model. OS engines: no download, no resident memory for us. The
  fallback names model downloads on first use and unloads after 60 s idle, only
  on platforms where the quality bar test picks it, and loads only when the
  Names toggle is on. Its peak under 150 MB applies to the fallback path only,
  stated per release (see Model downloads). Nothing resident when idle.

## 11.4 Snippets

- **Pattern:** G, always on. **Job:** "Type ;addr and get my address, in any app."
- **Stored:** snippets in an encrypted local SQLite database: trigger, name,
  group, content (plain, rich, or image), per-snippet options, use count. Same
  at-rest scheme and key handling as 11.1. Export to plain JSON on request.
- **Placeholders:** `{date}`, `{date +7d | DD MMM YYYY}`, `{time}`,
  `{clipboard}`, `{cursor}` (caret lands here), `{input:Name}` (small form
  before expansion), `{snippet:sig}` (nesting, depth limit 5). No shell or
  script execution unless the user turns on "Allow scripts" per snippet, off by default.
- **Keystroke handling (this is keylogger-shaped, so the rules are strict):**
  the matcher keeps only the last N characters in memory where N is the length
  of the longest trigger (default under 32). The buffer is never written to
  disk, is cleared on app switch, on any non-printing key, and whenever the OS
  reports secure input (password field). Nothing typed is stored or sent. A
  settings page shows the buffer length in plain words, and the code path is
  small enough to audit in one file.
- **Triggers:** prefix character default `;`, per-snippet "expand immediately"
  or "on space or Tab", case propagation (`;Addr` gives a capitalized result),
  word-boundary only. Excluded apps list (default: password managers, remote
  desktop clients).
- **Per OS:** macOS needs Input Monitoring plus Accessibility (event tap,
  and paste via synthetic Command+V). The tap callback must return in about a
  millisecond or macOS disables the tap, so the callback only pushes to a ring
  buffer. Windows uses a low-level keyboard hook and `SendInput`; it cannot type
  into elevated windows (UIPI). Linux X11 works via XInput record and XTest;
  Wayland has no global key capture, so it needs the evdev plus uinput route
  (espanso does this, needs the `input` group) or an input method (IBus or
  Fcitx), flagged "later". iOS cannot do system-wide expansion; ship a snippet
  picker in the share sheet and an optional keyboard (Full Access off by
  default). Android uses a keyboard (IME) only.
- **Edge cases:** expansion while the user keeps typing (cancel and restore the
  typed text); apps that swallow synthetic paste; clipboard restored after
  paste-based expansion (restore within 300 ms, marked transient so 11.1
  ignores it); IME composition (Chinese, Japanese, Hindi phonetic) suspends matching;
  international layouts where `;` needs a modifier.
- **Quality bar:** imports TextExpander CSV, Alfred `.alfredsnippets`, Raycast
  JSON, espanso YAML and macOS Text Replacements (formats confirmed in phase
  1). Expansion latency under 50 ms after the last trigger key. Beat TextExpander (subscription), Raycast
  Snippets and Alfred (Powerpack) on price, and espanso on macOS and Windows
  setup (no config files to start).
- **Engine:** Rust matcher, OS input APIs. **Surfaces:** global, bar
  (`snip <name>`), CLI `panoply snip list|add|expand`, MCP `snippet_expand`,
  `snippet_list` (names only, never contents without approval).
- **Budgets:** The second always-on module and the most sensitive. Idle: zero
  wake-ups (the keyboard hook is event driven and the callback does a ring-
  buffer push in under 50 microseconds, never touching the database or UI
  thread). Resident under 15 MB: the trigger set lives in a compact trie,
  snippet bodies load from the database only on expansion. Expansion starts
  under 50 ms after the last trigger key. The only memory that grows with
  typing is a fixed 32-character buffer.

## 11.5 Transform text

- **Pattern:** F (typed verb) and A (selection or clipboard). **Job:** "Change case, sort, dedupe, or clean this text."
- **Trigger:** `<verb> [<text>]`. With no text it acts on the selection, else
  the clipboard. Verbs: `upper`, `lower`, `title`, `sentence`, `camel`, `snake`,
  `kebab`, `pascal`, `const`, `sort`, `sort -n`, `sort -r`, `uniq`,
  `shuffle`, `join`, `unjoin`, `trim`, `squeeze` (collapse spaces), `slug`,
  `reverse`, `number` (line numbers), `prefix=`, `suffix=`, `wrap=80`,
  `smartquotes`, `straightquotes`, `extract email|url|number`.
- **Return copies** the result. Option+Return pastes it over the selection in
  the front app.
- **Edge cases:** reverse by grapheme cluster (family emoji and flags stay
  whole); `ß` uppercases to `SS`; Turkish dotless i under a Turkish locale;
  locale-aware sort (ICU collation: Swedish `å`, German `ä`) and natural sort
  (`file2` before `file10`); title case keeps small words lower (a, of, the)
  and acronyms; slug transliterates Latin accents, and for Devanagari and
  others uses ICU Any-Latin, else keeps Unicode; CRLF preserved; a 50 MB paste
  sorts without freezing (stream, progress after 300 ms).
- **Quality bar:** passes a case-conversion suite for camel/snake/kebab on
  inputs with digits, acronyms (`HTTPServer` gives `http_server`) and
  non-ASCII. Beat IT-Tools and Raycast text commands on grapheme-correct
  reverse and locale sort.
- **Engine:** Rust `unicode-segmentation`, ICU4X. **Surfaces:** bar, selection
  hotkey, CLI `panoply text transform <verb>`, MCP `text_transform`.
- **Budgets:** Pure CPU, no model. 1 MB of text transforms in under 20 ms, 50
  MB streams under 1 s per pass with constant memory (a sort spills to disk
  past 200 MB). Holds nothing when idle.

## 11.6 Count

- **Pattern:** F. **Job:** "How many words is this?" (top-30 #17, so the page
  must feel instant.)
- **Trigger:** `count [<text>]`, `wc`, or the hotkey on the current selection.
  Drop a file to count a document. With empty input it counts the clipboard.
- **Return copies** `412 words, 2,390 characters, 2 min read`. Option+Return
  copies the word count only.
- **Reports:** words, characters (with and without spaces), sentences,
  paragraphs, lines, UTF-8 bytes, reading time (default 238 words per minute,
  the Brysbaert 2019 meta-analysis figure for silent non-fiction reading,
  editable; speaking time at 150), X weighted length (CJK counts 2), top 10
  words excluding stopwords, and tokens via 13.17 on request.
- **Edge cases:** CJK and Thai have no spaces, so words come from ICU
  dictionary segmentation, characters shown too; Devanagari with ZWJ and
  ZWNJ; hyphenated words and apostrophes follow UAX 29; text inside markdown
  or HTML counts visible text only (option); `.docx`, `.pdf`, `.epub`, `.odt`
  read through the document engine (this replaces the duplicate row in section 6).
- **Quality bar:** within 0.5% of Microsoft Word's count on a corpus of 200
  English documents (differences are hyphen and em-dash rules, listed in the
  docs); 1 MB of text counts in under 50 ms. Beat wordcounter.net and Word on
  speed and on not uploading the text.
- **Engine:** Rust `unicode-segmentation`, ICU4X for dictionary break.
- **Surfaces:** bar, panel with live count, CLI `panoply text count`, MCP `text_count`.
- **Budgets:** Live count updates per keystroke without a UI-thread task over
  4 ms (counting runs incrementally off-thread). 1 MB counts in under 50 ms.
  Dictionary segmentation data for CJK and Thai loads only when those scripts
  appear in the text.

## 11.7 Find and replace across files

- **Pattern:** H with a preview step. **Job:** "Rename this thing in every file, and show me before it happens."
- **Inputs:** a folder or a file selection, a pattern, a replacement.
- **Options:** literal, regex (Rust syntax by default, PCRE2 for lookaround),
  whole word, case sensitive, **case-preserving** (`foo` to `bar`, `Foo` to `Bar`,
  `FOO` to `BAR`), multiline, include and exclude globs, respects `.gitignore`
  and hidden-file rules (default on), skip binary (default on), file types
  including `.docx` text.
- **Preview:** per-file diff with a checkbox per hunk, match counts, total
  files. Nothing is written until Apply. Return runs the preview, Apply is a
  separate explicit key.
- **Safety:** writes go to a temp file then atomic rename. Because a run can
  touch thousands of files, originals are stored in a content-addressed undo
  journal in the app data folder instead of one Trash entry each; Undo restores
  the whole run, kept 30 days. Preserves encoding, BOM, line endings, final
  newline and file mode. Symlinks are not followed.
- **Edge cases:** `.docx` splits words across runs (`<w:r>`), so match on joined
  run text and rewrite only the touched runs; files changed on disk between
  preview and apply (skip and report); Latin-1 and UTF-16 files detected, not
  assumed UTF-8; a regex that matches empty strings; a replacement that grows a
  file past 1 GB; read-only files.
- **Quality bar:** scans a 100,000-file repository no slower than `rg` (same
  crates), and a round trip (replace then undo) restores every byte, tested
  by hash. Beat VS Code Replace in Files on case-preserving replace and undo
  across sessions.
- **Engine:** ripgrep's `ignore` and `grep-regex` crates, `fancy-regex`.
- **Surfaces:** panel, right-click folder, CLI `panoply text replace`, MCP
  `text_replace` (dry run by default, a second call with `apply: true` writes).
- **Budgets:** Matches `rg` speed because it uses the same crates; a scan
  streams files, so memory is flat (under 100 MB) regardless of repository
  size. Preview diffs render lazily (virtualized list) so 50,000 hunks scroll
  at 120 fps. The undo journal is on disk, never in memory.

## 11.8 Diff text

- **Pattern:** I. **Job:** "What changed between these two pieces of text?"
- **Inputs:** two texts (select two clipboard history items, paste into left
  and right, or two files). Dropping two files starts it.
- **Options:** granularity (line, word, character), ignore whitespace, ignore
  case, ignore line endings, JSON-aware (sort keys, ignore formatting),
  side by side or inline, context lines.
- **Output:** copy as unified diff, or copy the right side with changes
  highlighted as HTML.
- **Edge cases:** minified single-line files (word diff capped, falls back to
  chunks); CRLF versus LF (offered as one click "ignore"); 100 MB inputs (line
  hashing, patience-style anchors); moved blocks flagged as moved, not as
  delete plus add.
- **Quality bar:** the unified diff applies cleanly with `patch` and matches
  `git diff --patience` hunks on a test corpus. Beat IT-Tools text diff and
  Diffchecker (uploads your text) on large inputs and on privacy.
- **Engine:** Rust `similar` crate (Myers, patience). **Surfaces:** panel,
  clipboard history multi-select, CLI `panoply text diff a b`, MCP `text_diff`.
- **Budgets:** Diff runs off the UI thread; first hunks appear under 100 ms
  even on 100 MB inputs (anchors first, refinement streamed in). Memory is
  line hashes, not text copies: under 3x the input size, capped at 300 MB with
  a graceful fall back to chunked diff.

## 11.9 Translate text

- **Pattern:** F (typed) and A (selection). **Job:** "Translate this, with no cloud."
- **Trigger:** `tr <lang> <text>` (`tr hi hello there`), `translate to hindi: <text>`,
  or hotkey on selection. Source language auto-detected (fast detector,
  lingua or whatlang class), shown, and overridable.
- **Return copies** the translation. Option+Return replaces the selection.
- **Models (🧠):** one small model per language pair, downloaded on first use
  with the size shown from the manifest before download. Candidates: Bergamot
  (Marian NMT, Mozilla) for common European and several Asian pairs; Opus-MT
  through CTranslate2 for the long tail (CC-BY); AI4Bharat IndicTrans2 for
  Indian languages (verify license and size). Models under non-commercial
  licenses (the NLLB family is CC-BY-NC) are not shipped. On Apple platforms an
  adapter can use the OS Translation framework when the pack is installed.
- **Edge cases:** long text is split by sentence and rejoined with the same
  line breaks; markdown, code spans, URLs and `{placeholders}` are protected
  and not translated; right-to-left output is displayed correctly; Hinglish
  (romanized Hindi) is not supported and detected as such; mixed-language
  input translates the dominant language and flags the rest.
- **Quality bar:** report chrF and COMET on FLORES-200 devtest per pair next to
  the model's published numbers; ship only pairs we can show. We claim offline
  and private, not "better than Google Translate".
- **Engine:** OS first, own model second. Translation: macOS and iOS use the
  Apple Translation framework (`TranslationSession`). Android uses ML Kit
  Translation (on-device, downloads per language). Windows: none found. Linux:
  none. Fallback model (any platform where the OS engine is absent, lacks the
  language pair, or fails the quality bar test in CI): a small permissive MT
  model per pair, run with bergamot-translator or CTranslate2 (CPU, int8).
  Language detection: macOS and iOS use `NLLanguageRecognizer`, Android uses ML
  Kit Language Identification. Windows and Linux use the fast detector (lingua
  or whatlang class). **Surfaces:**
  bar, selection hotkey, CLI `panoply text translate --to hi`, MCP `text_translate`.
- **Budgets:** Heaviest module in this file on the fallback path. OS engines:
  no download, no resident memory for us. The fallback translation model per
  pair is 100 MB class (size shown before download), downloads on first use and
  unloads 60 s after the last translation, only on platforms where the quality
  bar test picks it. Peak under 600 MB including the runtime applies to the
  fallback path only, an exception to the 300 MB cap with that reason. First sentence returns under
  300 ms warm on a laptop CPU, text streamed in sentence by sentence so the UI
  never waits for a whole page. Language detection is under 5 ms and never
  loads a translation model.

## 11.10 Scratchpad

- **Pattern:** G (persistent text). **Job:** "Jot something down without opening a notes app."
- **Stored:** plain Markdown files in a visible folder (default
  `Documents/Panoply/Scratchpad/`), one rolling note plus any named notes.
  Plain files so any tool can read them; optional per-note password using the
  Encrypt module. Autosave debounced 300 ms with atomic writes, so a crash
  loses at most the last keystroke.
- **Trigger:** `note <text>` appends the line with a timestamp to today's note
  and closes. `note` alone opens the panel. Command+Return from anywhere opens
  it with the cursor at the end.
- **Calc mode (optional, per note):** every line is evaluated with 12.1, so
  `rent = 25000` then `rent * 12` shows `300000`. This is the Soulver-style
  mode; it ships second.
- **Edge cases:** 10 MB paste (loads lazily); rich text paste becomes plain
  Markdown; two devices editing the same note (conflict copy, never merge
  silently); note folder moved or on a disconnected drive (falls back to the
  app data folder and says so).
- **Quality bar:** opens in under 100 ms from the hotkey and never loses
  typed text across a forced quit, tested by killing the process mid-typing.
  Beat Raycast Notes and macOS Quick Note on plain-file storage and speed.
  It is not a notes app: no tags, no folders, no sync service.
- **Surfaces:** global hotkey, bar, CLI `panoply note add`, MCP `note_append`
  (append only; reading needs approval).
- **Budgets:** Idle: nothing resident, the panel process exits after 60 s.
  Opens under 50 ms (reads only today's note). Autosave runs off the UI thread
  with atomic writes, no UI-thread task over 4 ms even in a 10 MB note (text
  view is virtualized). Calc mode evaluates only changed lines.

## 11.11 Emoji and symbols

- **Pattern:** F, with paste. **Job:** "Find that character."
- **Trigger:** any text after `e ` or the hotkey. Matches by name, CLDR keyword
  (in the UI language), GitHub shortcode (`:tada:`), codepoint (`U+1F389`,
  `1f389`), HTML entity (`&hearts;`), LaTeX name (`\alpha`), and ASCII
  shorthand (`->` finds `→`). Covers all of Unicode that a font on this
  device can draw, not only emoji: arrows, math, currency (`₹`), box drawing,
  Indic and other scripts.
- **Return** pastes into the app you came from (copy is the fallback if paste
  is not permitted). Command+Return copies only. Skin tone and gender
  preference remembered; recents and favorites first.
- **Edge cases:** characters the installed fonts cannot draw are hidden (a
  glyph-coverage check per OS), not shown as boxes; ZWJ sequences render as one
  item; paste needs Accessibility on macOS, with a copy-only fallback and a toast.
  Pasting a mystery string shows its codepoints and flags zero-width and
  look-alike characters (shared with 13.2).
- **Quality bar:** first result visible in under 50 ms of typing. Unicode data
  version is stated in About and updated with releases. Beat the macOS
  Character Viewer and Windows Win+. on search by keyword, codepoint and LaTeX,
  and Raycast Search Emoji on non-emoji symbols.
- **Engine:** UnicodeData, CLDR annotations, emoji-test.txt, bundled as one index.
- **Surfaces:** bar, hotkey, CLI `panoply char search`, MCP `char_search`.
- **Budgets:** Index is a memory-mapped file (not loaded into the heap):
  resident under 5 MB while the picker is open, released on close. First
  result under 50 ms of typing, grid scrolls at 120 fps with glyphs rasterized
  on demand. Glyph-coverage check is cached per font set.

# 12. Calculators and converters

Shared by 12.1 to 12.8: one parser and one decimal arithmetic core (arbitrary
precision decimal, never binary floats, so `0.1 + 0.2` is `0.3`). Modules
below are views on it that add their own trigger words.

## 12.1 Natural calculator

- **Pattern:** F. **Job:** "Do the sum I would say out loud."
- **Trigger grammar:** activates when the input starts with a digit, a
  currency symbol, `(`, `-`, a function name, or a variable, AND contains an
  operator, a unit word, or a percent. Examples: `15% of 2400` (360),
  `2400 + 15%` (2760), `2400 - 15%`, `40 is what % of 200` (20%),
  `20% off 1499`, `3 hours 20 min in seconds` (12000 s), `5 lakh + 3.5 lakh`
  (8.5 lakh), `2 crore / 12`, `0xff + 1 in hex`, `sqrt(2) * pi`,
  `rent = 25000` then `rent * 12`, `$120 in inr` (hands off to 12.3), `today + 90 days`
  (hands off to 12.5), `5 ft in cm` (hands off to 12.2).
- **Return copies** the number with its unit. A setting chooses Western
  (`1,234,567`) or Indian (`12,34,567`) digit grouping for display; copying
  never includes separators unless asked. `lakh` and `crore` are first-class words.
- **Edge cases:** `%` is relative to the left operand in `+` and `-` (so
  `100 + 10%` is 110) but modulo when between two bare numbers (`10 % 3`); a
  localized decimal comma (`1,5`) is accepted when the locale uses it and the
  reading is shown; implicit multiplication (`2(3+4)`); divide by zero says so;
  results past 30 significant digits shown in scientific form with the exact
  value one key away; mixed currency and unit sums refuse with a reason.
- **Quality bar:** a corpus of 500 phrases with expected answers, including the
  Soulver documentation examples we can reproduce. Beat Soulver and the
  Raycast calculator (built on Soulver's engine) on being free and open;
  Spotlight and PowerToys Run on phrase coverage (percent phrases, units,
  `lakh`); Alfred on precision.
- **Engine:** own parser on `rust_decimal` or `bigdecimal`; `fend-core` is a
  candidate to adopt for units and big numbers (verify license).
- **Surfaces:** bar inline, CLI `panoply calc "15% of 2400"`, MCP `calc`.
- **Budgets:** Parse and answer under 2 ms per keystroke so the bar never lags
  typing; the evaluator allocates nothing on the hot path beyond the result.
  Zero resident state: variables and history live in the Scratchpad file or
  the History store.

## 12.2 Units

- **Pattern:** F. **Job:** "How much is that in my units?"
- **Trigger:** `<number> <unit> in|to|as <unit>`, plus compound forms:
  `5 ft in cm`, `5'11" in cm`, `5 ft 11 in to cm`, `72 f to c`, `60 mph in km/h`,
  `500 g flour in cups`, `1 tola in g`, `10 gaj in sq ft`, `1 gb in mib`,
  `8 l/100km in mpg`. No target given shows the three likeliest targets.
- **Return copies** the converted value with its unit and a sensible number of
  digits (rounded for display, full precision on Option+Return).
- **Coverage:** length, mass, temperature, area, volume, speed, time, data,
  pressure, energy, power, angle, fuel economy, cooking (cup, tbsp, tsp, with
  US, UK, metric and Australian variants), plus Indian units (lakh, crore,
  tola, gaj, cent, acre, bigha).
- **Edge cases:** `bigha`, `guntha` and `cent` vary by state, so ask which
  state, never guess; ounce (mass or fluid), ton (metric, short, long), pint
  (US, UK), gallon (US, imperial), tablespoon (15 mL, 20 mL AU) are all
  ambiguous and shown as chips to pick; data: MB (1000) versus MiB (1024)
  stated in the answer; temperature is affine, not a ratio (`10 c to f` but
  `10 c per hour` is refused); fuel economy is inverse, not linear; ingredient
  conversions (flour, sugar, butter) use a small density table and say
  "about" with the density used.
- **Quality bar:** unit table generated from exact definitions (NIST SP 811
  factors stored as rationals) with a test per pair, and zero rounding drift
  on round trips. Beat Google's converter on offline and Indian units, Spotlight
  and Alfred on coverage, Soulver on being free.
- **Engine:** shared decimal core, unit table in a data file anyone can PR.
- **Surfaces:** bar, CLI `panoply unit 5ft cm`, MCP `unit_convert`.
- **Budgets:** Unit table (a few hundred rows) compiled into the binary, so no
  file read: under 1 ms. Density table for ingredients loads only when an
  ingredient word appears.

## 12.3 Currency

- **Pattern:** F, 🌐. **Job:** "What is that in rupees?"
- **Trigger:** `<amount> <code|symbol> in|to <code|symbol>`, `usd inr` (rate
  only), `$100 to ₹`, `₹5 lakh in usd`, `100 eur`. Bare amount with only a
  source uses the home currency from the device region.
- **Return copies** the converted amount with the currency's own decimals
  (ISO 4217: JPY 0, KWD 3, INR 2).
- **Network:** one request per day to the Panoply release mirror for a static
  rates file (a few KB). It carries no user data. The mirror builds that file
  daily from ECB euro reference rates (about 30 currencies, published on
  working days); long-tail currencies and crypto are not in the default feed.
  The Privacy line says "rates fetched once a day from the Panoply mirror,
  nothing about you is sent". Offline: last cached rates, always shown with
  their date and source (`rates 12 Oct, ECB, mid-market`). These are not the
  rate your bank or card charges, and the card says so in plain words.
- **Edge cases:** weekend and holiday (last published rate, dated); `$` means
  USD by default but `CAD`, `AUD`, `MXN` regions flip it, shown as a chip;
  `¥` is JPY or CNY, `kr` is four currencies, `Rs` is INR; a currency not in the
  feed says so and offers a manual rate; stale data over 7 days gets a warning.
- **Quality bar:** result equals the published ECB cross rate to the displayed
  digits; works offline after the first fetch. Beat Google and Raycast
  currency on showing the rate date and source, and Alfred on offline.
- **Engine:** cached JSON, decimal core. **Surfaces:** bar, CLI `panoply currency 100 usd inr`, MCP `currency_convert`.
- **Budgets:** Network fetch is once a day, a few KB, off the UI thread, never
  blocking an answer (the cached file answers in under 1 ms). Cache under 20
  KB on disk. No background wake-up for refresh: it refreshes lazily on the
  first use after 24 h.

## 12.4 Time zones

- **Pattern:** F, with a planner panel. **Job:** "What time is it there, and when can we meet?"
- **Trigger:** `3pm ist in pst`, `time in tokyo`, `9am london to sf`,
  `10:30 pt to ist`, `tz <city>`, `meet nyc, london, bangalore` (opens planner).
- **Return copies** `3:00 PM IST = 1:30 AM PST (Tue)`.
- **Planner:** up to 6 zones as 24-hour strips, working-hours overlap
  highlighted (default 9 to 18 local, editable), click a slot to copy invite
  text with each person's local time.
- **Edge cases:** abbreviations are ambiguous (IST is India, Ireland, Israel;
  CST is US, China, Cuba), resolve by device region and show the interpretation
  as a chip; a nonexistent local time in a spring-forward gap
  (`2:30am` on the change day) and an ambiguous time in a fall-back hour both
  say so and show both; half-hour and 45-minute zones (India, Nepal); places
  that changed rules recently (tzdata updates ship with releases and the OS
  database is used where newer); city names resolved through an alias table,
  not only IANA names.
- **Quality bar:** matches the IANA tz database on a generated test of
  transition instants for 50 zones and all dates 2000 to 2040. Beat World Time
  Buddy on offline and no ads, Raycast and Alfred on ambiguity handling.
- **Engine:** `chrono-tz` or ICU4X, bundled tzdata. **Surfaces:** bar, panel,
  CLI `panoply time zone`, MCP `time_convert`.
- **Budgets:** tzdata is compiled in or read from the OS database (about 1 MB,
  memory-mapped, not parsed up front). Answer under 2 ms. Planner redraws at
  120 fps while dragging the time slider.

## 12.5 Dates

- **Pattern:** F. **Job:** "How many days until, between, or after?"
- **Trigger:** `days until dec 25`, `days between 1 jan and 15 mar`,
  `today + 90 days`, `15 aug 2027 - 3 months`, `age of 14 mar 1995`,
  `working days between 1 nov and 30 nov`, `add 10 working days to 3 nov`,
  `week number of 1 jan 2027`, `what day is 15 aug 2027`.
- **Return copies** the result in the shortest clear form (`73 days`,
  `31 Oct 2026`, `31 years, 6 months, 28 days`).
- **Edge cases:** day-first versus month-first (`04/05/2026`) follows the
  device locale and shows its reading as a chip; adding months clamps to month
  end (31 Jan + 1 month is 28 or 29 Feb, stated); born on 29 Feb (shows
  both common legal readings for non-leap years); working days use the user's
  weekend (Sat and Sun, Fri and Sat, or Sun only) and an optional holiday list
  (bundled national holiday files for a few countries as dated data, plus
  user `.ics` import); proleptic Gregorian before 1582 with a note; ISO
  weeks.
- **Quality bar:** property tests (`(d + n) - d = n`) over 100 years, and
  working-day counts equal Excel `NETWORKDAYS` on a corpus. Beat Soulver and
  timeanddate.com on speed, and Spotlight on coverage.
- **Engine:** Rust `jiff` or `chrono`. **Surfaces:** bar, CLI `panoply date`, MCP `date_calc`.
- **Budgets:** Under 2 ms per answer. Holiday files (a few KB per country)
  load only when a working-day question names them.

## 12.6 Loan and EMI

- **Pattern:** F, with schedule panel. **Job:** "What will I pay each month, and in total?"
- **Trigger:** `emi 50 lakh 8.5% 20 years`, `emi 5000000 8.5 20y`,
  `loan 500000 at 9% for 36 months`, `flat 500000 11% 3y` (flat-rate loan).
- **Return copies** the monthly installment, rounded as banks do (to the nearest
  rupee, or the currency's minor unit). Panel shows total interest, total
  payment, and the amortization schedule (copy as table, export CSV or PDF).
- **Formula:** EMI = P r (1+r)^n / ((1+r)^n - 1), r = annual rate / 12. Test
  vector: 50,00,000 at 8.5% for 20 years is 43,391 a month.
- **Options:** reducing balance (default) or flat rate (shows the effective
  rate, since flat 11% is not 11% a year), prepayment (lump sum or extra per
  month: reduce tenure or reduce EMI), rate change mid-loan (floating),
  moratorium, processing fee folded into the true IRR, first-installment
  broken-period interest, annual versus monthly compounding.
- **Edge cases:** zero interest (P / n, not a divide by zero); last installment
  adjusted for rounding drift so the balance ends at exactly zero; tenure in
  years and months; rate given as a decimal (`0.085`) detected and confirmed.
- **Quality bar:** matches the closed form to the paisa on 1,000 random
  cases, and published bank schedule PDFs where we can obtain them. Beat bank
  calculators on having prepayment and flat-rate effective rate in one view,
  and Soulver on a real schedule.
- **Engine:** decimal core, IRR by Newton with bisection fallback.
- **Surfaces:** bar, panel, CLI `panoply loan emi`, MCP `loan_emi`.
- **Budgets:** A 30-year monthly schedule is 360 rows, computed under 1 ms;
  the schedule table is virtualized for long loans and exports a 1,000-row
  schedule to PDF under 200 ms.

## 12.7 Tax

- **Pattern:** F. **Job:** "Add or remove GST, VAT or sales tax."
- **Trigger:** `gst 18% on 2400`, `2400 + 18% gst`, `2832 incl gst 18`,

- **Quality bar:** every rate row carries a source link and an effective date,

- **Engine:** decimal core, rate table in data. **Surfaces:** bar, CLI

- **Budgets:** Shares 12.1's core: under 2 ms, no extra memory. Rate table (a

## 12.9 Health

## 12.10 Timers

- **Pattern:** F, stateful. **Job:** "Start a timer, stopwatch or pomodoro."
- **Trigger:** `timer 25m`, `timer 1h30 tea`, `countdown until 18:00`,
  `stopwatch`, `pomodoro` (25 work, 5 break, 15 long break after 4), `remind me in 10 min to call mom`.
- **Return starts** the timer (it does not copy; Command+C copies the remaining time).
  Several named timers run at once. Menu bar or tray shows the nearest one.
- **State:** stores the absolute end time, not "remaining", so a timer survives
  quit, sleep and reboot. After sleep, a missed timer fires immediately with
  "ended 4 min ago".
- **Edge cases:** DST changes during a long timer (uses absolute instants, not
  wall-clock); notifications blocked by the OS (falls back to a window and
  sound, says how to allow); phones schedule an OS local notification so it
  fires with the app closed; focus modes (alert shown when allowed, queued otherwise).
- **Quality bar:** fires within 1 second of target across a sleep and wake test
  on every desktop OS. Beat the macOS Clock and Siri timers on named multiples
  and menu bar visibility, Raycast timers on being offline-first and open.
- **Surfaces:** bar, menu bar, CLI `panoply timer start 25m`, MCP `timer_start`.
- **Budgets:** The one stateful instant module. A running timer must not keep
  the CPU awake: it sets a single OS timer for the end time (a `dispatch`
  timer, Windows waitable timer, systemd timer, or a scheduled local
  notification on phones), so wake-ups are exactly one per timer, zero while
  it counts down. A stopwatch display redraws only while visible (one repaint
  a second, 60 fps only during the final-seconds animation). Resident under 5
  MB while any timer exists, nothing when none.

## 12.11 Random

- **Pattern:** F. **Job:** "Pick one, roll, flip."
- **Trigger:** `pick pizza, sushi, tacos`, `roll 2d6`, `roll 4d6kh3`, `roll d20+5`,
  `flip`, `random 1-100`, `shuffle a, b, c, d`, `random 5 of 1-49`.
- **Return copies** the result. Command+R rolls again (Return stays "copy").
- **Edge cases:** unbiased range selection by rejection sampling (no modulo

- **Surfaces:** bar, CLI `panoply random`, MCP `random_pick`.
- **Budgets:** Under 1 ms. No tables, one `getrandom` call per roll, no

# 13. Developer tools

Shared by every module here: input comes from the bar, the clipboard, a
dropped file, or stdin in the CLI. Anything over 300 ms shows progress. Text
fields never silently truncate. Modules that touch credentials (13.3, 13.4,
13.6, 13.15) opt out of History.

## 13.1 Data formats

- **Pattern:** A on files and clipboard text; the bar also accepts `json`,
  `yaml`, `xml`, `toml`, `csv` as verbs on the clipboard.
- **Job:** "Format, validate or convert this JSON, YAML, XML, TOML or CSV."
- **On drop or paste:** detect the format from content (not extension), report
  validity with line and column and a caret on the error, and offer the three
  likeliest targets. Options: indent (2, 4, tab), sort keys, compact, JSONPath
  or jq-style query box, tree view.
- **Output:** converted text on the clipboard or `name (yaml).yaml` next to the source.
- **Edge cases:**
  - Integers beyond 2^53 are kept exactly (browser `JSON.parse` silently
    corrupts them, and so do several online tools).
  - JSONC, JSON5, trailing commas and comments accepted with a notice, written
    out strictly unless asked.
  - YAML 1.2 by default with a warning when a YAML 1.1 reading would differ
    (`no`, `on`, `0123`, the "Norway problem"); anchors and aliases expanded
    with an expansion-size limit (billion-laughs guard); YAML comments are lost
    on conversion and the card says so.
  - XML to JSON uses a documented convention (`@attr`, `#text`), namespaces
    kept, repeated elements become arrays, and the reverse is lossless for
    data produced by it.
  - CSV: delimiter sniffing, quoted newlines, BOM, Windows-1252 versus UTF-8
    detection, ragged rows flagged, type inference off by default (so
    `00123` stays text).
  - Files over 1 GB stream; tree view is virtualized.
- **Quality bar:** round-trip tests per pair on a corpus including real-world
  messy files, and error positions identical to the reference parsers. Beat
  IT-Tools and jsonformatter-style sites on big integers, size limits (none)
  and privacy, `jq` and `yq` on being usable without learning a query language.
- **Engine:** `serde_json` (arbitrary precision, order preserving), a maintained
  YAML crate (serde_yaml itself is archived), `quick-xml`, `toml_edit`, `csv`.
- **Surfaces:** bar, panel, right-click, CLI `panoply data fmt|convert|validate`, MCP `data_convert`.
- **Budgets:** Streaming parsers: peak memory flat under 300 MB for a 1 GB
  file (tree view loads children on expand, no whole-document DOM). Parse and
  format of 1 MB under 30 ms; the first 1,000 tree rows appear under 100 ms on
  any size. Convert is single pass, never two full copies.

## 13.2 Encode and decode

- **Pattern:** F (and A for files). **Job:** "Base64 or URL-encode this, or decode it."
- **Trigger:** `b64 <text>`, `b64d <text>`, `b64url <text>`, `b32`, `b58`,
  `hex <text>`, `unhex <hex>`, `urlenc <text>`, `urldec <text>`, `html <text>`
  (entities), `unhtml`, `esc <text>` (`\uXXXX` escapes), `unesc`, `puny <domain>`,
  `unicode <text>` (codepoint inspector). A bare string that is certainly one
  of these (a `data:` URI, a `%xx`-heavy URL, `eyJ...` which goes to 13.3) is
  recognised without a verb and offered as a suggestion, never auto-run.
- **Return copies** the output. If the decoded bytes are not valid UTF-8,
  the row shows `binary, 1,204 bytes, looks like PNG` and Return saves it as a file.
- **Edge cases:** base64 with newlines or spaces, missing padding, URL-safe and
  standard alphabets mixed (accepted, converted, noted); URL encoding of space
  as `%20` versus `+` (form encoding) is a toggle with the default for the
  context; `encodeURI` versus `encodeURIComponent` differences named; `data:`
  URIs show a preview for images; the `unicode` view lists each codepoint
  with name and UTF-8 and UTF-16 bytes and flags zero-width, bidi-override and
  look-alike (homoglyph) characters, which is how a pasted string with a
  hidden character is found.
- **Quality bar:** RFC 4648 test vectors for every base, fuzzed round trips.
  Beat CyberChef's auto-detect (Magic) on start-up and a single keystroke
  flow, and IT-Tools on being offline and handling binary.
- **Engine:** Rust `base64`, `data-encoding`, `percent-encoding`, `idna`.
- **Surfaces:** bar, CLI `panoply encode b64 <text>` and `panoply decode`, MCP `encode_decode`.
- **Budgets:** Under 1 ms for text. Files stream in 1 MB chunks with constant
  memory. Nothing resident when idle.

## 13.3 JWT

- **Pattern:** I (F trigger). **Job:** "What is in this token, and is it still valid?" Opts out of History.
- **Trigger:** `jwt <token>`, or a clipboard or typed string matching
  `^eyJ[\w-]+\.eyJ[\w-]+\.[\w-]*$` (specific enough to auto-suggest).
- **Return copies** the pretty-printed payload JSON.
- **Shows:** header, payload, `exp`, `iat`, `nbf` as local time and relative
  (`expired 3 h ago`), `alg`, `kid`, `iss`, `aud`; warnings for `alg: none`,
  HS256 where a public key is expected (algorithm confusion), missing `exp`,
  and "this token is not expired, treat it as a password".
- **Verify (optional):** paste an HMAC secret, a PEM public key, or a JWKS
  document. HS, RS, PS, ES and EdDSA families. Nothing is fetched: Panoply
  never downloads a JWKS by itself.
- **Edge cases:** JWE (encrypted) tokens cannot be decoded and are identified as
  such; malformed base64 segments say which segment is broken; very large
  claims; nested JWTs; tokens with extra whitespace or a `Bearer ` prefix.
- **Quality bar:** decode matches `jsonwebtoken` and `pyjwt` on the RFC 7515
  to 7520 test vectors. Beat jwt.io on never sending, storing or logging the token.
- **Surfaces:** bar, CLI `panoply jwt decode` (reads stdin), MCP `jwt_decode`
  (decode only; verification keys are not accepted over MCP).
- **Budgets:** Decode under 1 ms. Signature verification (RSA) under 10 ms. No
  resident state, nothing cached, nothing written.

## 13.4 Hashes

- **Pattern:** F for text, A for files. **Job:** "Hash this text or file."
- **Trigger:** `md5 <text>`, `sha1`, `sha256`, `sha512`, `sha3-256`, `blake3`,
  `crc32`, `hash <text>` (shows the common set), `hmac sha256 key=<k> <text>`,
  `bcrypt <text>` (cost 12), `bcrypt verify <text> <hash>`. Drop a file for
  every common digest at once, streamed.
- **Return copies** lowercase hex. Option+Return copies the uppercase or
  base64 form.
- **Edge cases:** `echo` adds a trailing newline that `echo -n` does not: the
  panel shows both hashes when the text could have a newline, with a chip
  "with trailing newline"; text is hashed as UTF-8 (a toggle for UTF-16LE,
  which Windows tools use); bcrypt truncates at 72 bytes (warned), accepts
  `$2a$`, `$2b$`, `$2y$`, and shows the time taken; MD5 and SHA-1 carry a
  small "not for security" tag; hashing a 50 GB file streams in constant memory.
- **Quality bar:** NIST CAVP and RFC test vectors; file hashing at disk speed
  (`b3sum`-class for BLAKE3). Beat IT-Tools and macOS `shasum` on showing all
  digests in one read, and 7-Zip's hash menu on batch and verification.
- **Engine:** RustCrypto and `blake3`. 13.4 and 14.5 share one engine, and the
  Files module's Checksums is the same module (see merge notes).
- **Surfaces:** bar, right-click "Hash", CLI `panoply hash sha256 <file>`, MCP `hash_compute`.
- **Budgets:** File hashing at disk speed (limited by the drive, not CPU:
  BLAKE3 and SHA-256 use SIMD and hardware instructions), constant memory
  under 10 MB (1 MB read buffer per thread). bcrypt at cost 12 takes about a
  quarter second by design; it runs off the UI thread with a progress dot and
  cancel.

## 13.6 Passwords

- **Pattern:** E (panel), F (bar). **Job:** "Make a strong password or passphrase."
  Same module as the top-30 "Password generator", one spec. Opts out of History.
- **Trigger:** `password`, `pw 24`, `pw 16 nosymbols`, `passphrase 5`,
  `pin 6`, `pw site=bank` (applies a saved site rule).
- **Options:** length (default 20), classes, exclude look-alikes (`0O1lI`),
  passphrase from the EFF large wordlist (7,776 words, about 12.9 bits a

  (max length, forbidden characters) saved by name.
- **Shows:** entropy computed from the generator's real choices, not a
  guess. An existing password pasted into the checker uses a zxcvbn-style
  estimator and is labelled an estimate.
- **Return copies** and marks the clipboard item concealed so 11.1 skips it;
  the clipboard is cleared after 30 seconds if unchanged (setting).
- **Edge cases:** uniform selection by rejection sampling; "at least one of each

  sites that reject some symbols; a password shown on screen hides on lock or

  written to disk, logs or History. Beat browser built-ins and web generators

  60 KB, memory-mapped).

# 14. Privacy and security

## 14.1 Clean before sharing

- **Pattern:** I, with the fix applied automatically on send. **Job:** "Remove location and hidden data before I send this."
- **On drop:** scan and list what is hidden, with values: GPS position, device
  make, model and serial, lens, software, author, last-modified-by, company,
  comments and tracked changes, hidden sheets and text, revision history,
  embedded thumbnails, XMP, edit history, and file-system extras.
- **Where it runs automatically:** Send to device, the share sheet, and the
  right-click "Share clean". It cannot intercept another app's own attach
  button, and the app says so.
- **Per format:** JPEG by removing segments without re-encoding (no quality
  loss); PNG ancillary chunks (`tEXt`, `iTXt`, `eXIf`, `tIME`); MP4 and MOV
  (`udta`, QuickTime `©xyz` location, `meta`); PDF (Info dictionary, XMP,
  embedded files, JavaScript, **and old revisions kept by incremental saves**, by
  rewriting the file in full); Office (`docProps`, comments, tracked changes,
  custom XML, hidden sheets, external links); macOS extended attributes
  (`kMDItemWhereFroms`, the download URL, and quarantine) and Windows
  `Zone.Identifier` alternate data streams (referrer URL).
- **Options:** policy preset (Location only, Personal data, Everything), keep
  the ICC color profile (default on) and the orientation (applied to pixels
  or kept as a tag so photos do not rotate), clean filename option.
- **Result card:** `Removed: GPS (12.97, 77.59), iPhone 15 Pro, author "A. Abidi", 3 comments.`
- **Edge cases:** stripping orientation flips portrait photos sideways; Live
  Photos and motion photos (the video part has its own metadata); HEIC with
  auxiliary images (depth maps carry nothing personal but are optional to drop);
  signed PDFs lose the signature, warned first; DRM files refused.
- **Quality bar:** on a corpus, `exiftool` finds no GPS or personal tag in outputs,
  JPEG pixels are bit-identical, and MP4 plays identically. Beat `exiftool -all=`
  (strips orientation and color profile and recompresses nothing, but needs a
  command line), the Apple share sheet "Location" toggle (location only), and
  Windows "Remove Properties" (partial).
- **Merge:** the strip half of "Metadata for any file" in Files; this is its
  preset-driven face.
- **Engine:** `little_exif`/own segment walker, `lopdf`/pdfium, zip and XML. **Surfaces:** right-click, Send flow, CLI
  `panoply clean <file>`, MCP `file_clean`.
- **Budgets:** Lossless paths (JPEG segment removal, PNG chunk removal, MP4
  box rewrite) are streaming copies at disk speed with constant memory; no
  pixel decode. PDF rewrite and Office repack follow the 300 MB cap. Scan
  report appears under 100 ms. When wired into Send, it adds under 50 ms to a
  5 MB photo.

## 14.2 Auto-redact

- **Pattern:** C (review) fed by I (detection). **Job:** "Find and permanently hide personal data in this document or image." 🧠
- **Inputs:** PDF (text or scanned), images, DOCX. Shares the detection engine
  with 11.3 and with "Mask ID numbers" in section 2 (one engine, three surfaces).
- **Detects:** the 11.3 list plus dates of birth, addresses and names (model),
  passport numbers by country format, MRZ lines, signatures and faces
  (optional detectors), and a user list of exact strings to always hide.
- **Review:** each detection is a box with a checkbox, grouped by category;
  "hide this value everywhere" applies to every occurrence on every page.
  Style: solid block, or mask but show last 4 digits.
- **True redaction:** the text is removed from the file, not covered. Scanned
  pages have the pixels burned and the OCR layer rebuilt without the text.
  Metadata, thumbnails, previous incremental revisions, and annotations are
  stripped. **Self-check:** after saving, Panoply extracts all text and OCRs
  the pages again and reports `0 of 14 redacted values found in the output`.
- **Output:** `name (redacted).pdf`; always a new file.
- **Edge cases:** text drawn as vector outlines; text in images inside PDFs;
  split across lines or with soft hyphens; ligatures; right-to-left text;
  values in form fields, bookmarks, link targets, and attachments.
- **Quality bar:** the self-check passes on 100% of outputs on the corpus (a
  deterministic test), and recall by category is published, favoring recall at
  the default because the user reviews. Beat Acrobat Pro's pattern search on
  Indian IDs and on cost, and "draw a black box" workflows on actually removing text.
- **Engine:** pdfium, regex and checksums for structured IDs, plus three ML
  jobs, each with its own ladder. OS first, own model second. OCR for scanned
  pages and images: macOS and iOS use Apple Vision `VNRecognizeTextRequest`, and
  `RecognizeDocumentsRequest` (iOS and macOS 26). Android uses ML Kit Text
  Recognition v2 (Latin, Chinese, Devanagari, Japanese, Korean). Windows uses
  `Windows.Media.Ocr` (`OcrEngine`), and the Windows AI Text Recognition API on
  Copilot+ PCs. Linux: none. Fallback model: the PaddleOCR-class OCR engine from
  section 7 (Apache-2.0). Names and addresses: macOS and iOS use Apple
  NaturalLanguage `NLTagger` (people, places, organizations). Android uses ML
  Kit Entity Extraction (structured entities such as dates and addresses, not
  person names). Windows: none found. Linux: none. Fallback model: the small
  names model (ONNX Runtime) plus regex and checksum validators. Faces (optional
  detector): macOS and iOS use Apple Vision `VNDetectFaceRectanglesRequest` and
  `VNDetectFaceLandmarksRequest`. Android uses ML Kit Face Detection. Windows
  uses `Windows.Media.FaceAnalysis` (detection only). Linux: none. Fallback
  model: YuNet (MIT). Signature detection: OS engine: none. Own model on every
  platform. Each fallback model is used on any platform where the OS engine is
  absent or fails the quality bar test in CI.
- **Surfaces:** panel, right-click, CLI `panoply redact <file>`, MCP `file_redact`.
- **Budgets:** Heavy path: detection can OCR a scanned document and run the
  names model. Pages are processed one at a time and streamed, so a 500-page
  PDF stays under the 300 MB peak. OS engines: no download, no resident memory
  for us. The fallback OCR, names, face and signature models download on first
  use and unload 60 s after the last job, only on platforms where the quality
  bar test picks them. First detection box appears under 100 ms for
  a text-layer page; scanned pages show boxes as OCR completes, page by page.
  Review view scrolls at 120 fps with page bitmaps tiled.

## 14.4 Password breach check

- **Pattern:** I, 🌐. **Job:** "Has this password leaked?" Opts out of History.
- **Input:** a masked field (never the bar, whose text can be captured), or a
  password manager CSV export dropped on the window.
- **What leaves the device:** the first 5 hex characters of the password's SHA-1
  hash, sent to the Have I Been Pwned range API over HTTPS with response
  padding on. The server returns every hash suffix for that prefix with a
  count and the comparison is local. The Privacy line says exactly this. No cookies, no account,
  no API key.
- **Shows:** `Seen 12,345 times in leaks` or `Not found`, with a reminder that
  not found is not proof of safety.
- **Batch:** a CSV of logins is read locally and passwords are checked by
  unique prefix; only entries are shown, and passwords are never displayed or
  copied. Offers to shred the CSV afterwards (14.3).
- **Offline fallback:** a bundled Bloom filter of the most common passwords
  (1,000,000 entries at a 1% false-positive rate is about 1.2 MB) answers
  "common password" when there is no network and says it is a weaker check.
- **Edge cases:** the network is down (fallback, labelled); a corporate proxy
  that rewrites responses; a very short password (flagged weak before checking);
  a passphrase with spaces and Unicode (UTF-8 NFC normalised, noted).
- **Quality bar:** result equals the official site's for 1,000 test passwords;
  the request is verified by test to contain only the 5-character prefix.
  Beat the website on batch and offline fallback, and password manager
  breach reports on not needing an account.
- **Surfaces:** panel, CLI `panoply breach` (reads stdin), MCP
  `password_breach_check` (accepts a SHA-1 hash only, never a plaintext password).
- **Budgets:** One HTTPS request per unique prefix, under a few KB each, with
  a 5 s timeout; the response (about 1 MB at most for a prefix) is streamed
  and compared without being kept. A 5,000-row CSV batch runs concurrently
  with a politeness cap. Bloom filter (about 1.2 MB) memory-mapped, used only
  when offline. Nothing resident.

## 14.5 Verify downloads

- **Pattern:** I. **Job:** "Is this file the one the publisher released?"
- **Input:** a file, plus an expected hash pasted, a `SHA256SUMS` or `.sha256`
  file, or a signature file. Panoply looks next to the file for sibling
  checksum and `.asc`/`.minisig` files.
- **Checks:** hash by auto-detected algorithm from length (32 hex MD5, 40 SHA-1,
  64 SHA-256 or SHA3-256 or BLAKE2s, tries all); GPG detached signatures
  (needs the publisher's key; the key fingerprint is shown to compare with a
  trusted source); minisign; macOS code signature and notarization status;
  Windows Authenticode signature, publisher and timestamp.
- **Result:** one clear line, a green or red state, and for a mismatch the
  likely cause (truncated download, wrong file, a text-mode newline change).
- **Edge cases:** checksum files in GNU (`hash  name`, `hash *name`) and BSD
  (`SHA256 (name) = hash`) styles; uppercase and lowercase; whitespace pasted
  with the hash; 100 GB files stream; the hash page was itself tampered with,
  and the card says a hash from the same server proves integrity, not origin.
- **Quality bar:** correct verdict on a corpus including truncated, renamed and
  re-compressed files. Same hash engine as 13.4. Beat `shasum -c` on legibility
  and 7-Zip's hash tool on signatures.
- **Surfaces:** right-click "Verify", CLI `panoply verify <file> [hash]`, MCP `file_verify`.
- **Budgets:** Hashing as 13.4: disk speed, constant memory. Signature checks
  use the OS's own verifier for code signatures (macOS and Windows), so no
  extra library is loaded for them.

# 15. Business paperwork

Shared by 15.1, 15.2 and the India set: a **business profile** saved once in
Settings and used to pre-fill every generator. It holds legal name and trade
name, address, logo, signature and stamp images, tax IDs (GSTIN and PAN, or VAT

## 15.1 Invoice maker

- **Pattern:** E. **Job:** "Make a proper, numbered invoice and send the PDF."
- **Inputs:** none. The form opens with the last used template, business
  profile filled, the client picked from the book (typing a GSTIN fills the
  client name and state from a prior invoice or leaves it for the user; no
  lookup is made).
- **Tax modes:** India GST (CGST plus SGST when supplier and place of supply
  are in the same state, IGST otherwise; place of supply shown with state name
  and code; reverse charge Y or N; composition dealers get a "Bill of supply"
  with no tax; exports under LUT print the LUT statement with zero IGST), EU and UK
  VAT (reverse-charge wording; VAT ID shape checked per country, online VIES
  check is an explicit 🌐 action, not default), US sales tax (one line), no tax.
- **Numbering:** a series per financial year, default `INV/2026-27/0001`. India
  rules: serial numbers are consecutive, unique, and at most 16 characters
  using letters, digits, `-` and `/`, so the form refuses anything else. A
  number is never reused or skipped: a deleted invoice becomes "Cancelled",
  kept in the register.
- **Lines:** description, HSN or SAC (from 15.3d, digits per the profile's
  turnover band), quantity, unit, rate, discount (before tax), tax rate;
  catalog autocomplete; "round-off" line shown when the total is rounded to
  the rupee. India shows the total in words using lakh and crore.
- **Pay QR:** India prints a UPI QR (15.3f) with the amount and the invoice
  number as the reference; Eurozone uses an EPC QR ("GiroCode", EPC069-12);
  otherwise bank details as text.
- **Preview:** the PDF page live beside the form, totals and tax table
  recomputed on every keystroke.
- **Output:** PDF into `Documents/Panoply/Invoices/FY2026-27/`, named
  `INV-2026-27-0042 Acme.pdf`; embedded fonts (Noto, for Indic and RTL client
  names); also a JSON copy of the record. Phase 2: PDF/A-3 with embedded
  Factur-X or ZUGFeRD XML and UBL for EU e-invoicing, and the India e-invoice
  JSON (IRP schema) for upload to the government portal. Panoply does not
  generate an IRN or talk to the IRP, and says so.
- **Result card:** `INV/2026-27/0042, Rs 2,36,000.00 incl. IGST 18%, PDF 84 KB, saved.`
  Actions: Mark sent, Record payment (makes a receipt, 15.2), Duplicate, Credit note.
- **Edge cases:** rounding per line versus per invoice mismatches (shown, setting);
  discounts and tax on discounts; advance payments; credit and debit notes that
  reference the original number; multi-currency export invoices with an INR
  equivalent; a client in a state the profile has not seen; very long item
  descriptions that must wrap rather than clip; Hindi, Tamil and other Indic
  text shaped correctly (HarfBuzz).
- **Quality bar:** tax arithmetic shares one library with 12.7 and is checked
  against hand-worked examples from the CBIC invoice rules; every mandatory
  field of Rule 46 CGST is present or the form blocks "Finalize". Beat Invoice
  Ninja (self-hosted, needs setup), Zoho Invoice, Wave and Vyapar on needing no
  account and no server, having no branding watermark, and running offline.
- **Engine:** Typst compiled in process (templates are plain text users can edit;
  Apache-2.0, verify), `rust_decimal`, HarfBuzz. **Surfaces:** panel, bar
  (`invoice`), CLI `panoply invoice new|list|pdf`, MCP `invoice_create`
  (creates a record, so it asks for confirmation).
- **Budgets:** Typst compiles in process: a one-page invoice renders under 100
  ms and updates the live preview per keystroke after a 150 ms debounce
  (compile off the UI thread, previous page stays on screen, no flicker).
  Fonts are loaded as subsets, Noto Indic and RTL faces only when the text
  needs them. Resident while the form is open under 80 MB, released on close.
  Idle: nothing.

### 15.3c Delivery challan

### 15.3d HSN and SAC finder

- **Pattern:** F. **Job:** "What is the HSN or SAC code, and the GST rate, for this?"
- **Trigger:** `hsn laptop`, `hsn 8471`, `sac consulting`, `sac 9983`,
  `hsn mobile phone`. Fuzzy and synonym search on descriptions, plus prefix
  match on code.
- **Return copies** the code. Option+Return copies
  `8471 | Automatic data processing machines | 18%`.
- **Data:** bundled table from the official CBIC HSN master and SAC list: code,
  description, chapter and heading path, GST rate with effective date and the
  notification it comes from, exemption and nil-rated flags, and conditions
  (some rates depend on price or form). Refreshed each release by a script
  whose diff is reviewed. HSN is 2, 4, 6 or 8 digits; SAC is 6 digits starting
  `99`.
- **Shows:** the digit length required for your turnover band from the profile
  (a dated rule with the notification, not hard-coded), the heading path
  so the user can step up and down, and a clear line when a rate has conditions:
  `18%, as of <date>, rate depends on conditions, see notification`.
- **Edge cases:** a product that fits two headings (both shown with the
  classification rule notes); retired or merged codes (mapped forward); typed
  with dots or spaces; services versus goods confusion (offers the other side);
  rate changes, which is why every rate shows its date.
- **Quality bar:** search puts the correct code in the top 3 for a set of 300
  common product and service phrases we write and publish; every code in the
  table appears in the official list. Beat the CBIC portal search and
  ClearTax-style web finders on offline and speed.
- **Engine:** in-memory trigram index over a compressed table. **Surfaces:**
  bar, invoice item picker, CLI `panoply in hsn`, MCP `in_hsn_lookup`.
- **Budgets:** Data table is the budget item: compressed on disk, memory-
  mapped, trigram index built at release time, not at runtime. Resident while
  searching under 10 MB, released on close. Results under 20 ms per keystroke.

### 15.3e GSTIN check

- **Pattern:** F, with India ID checks. **Job:** "Is this GSTIN valid?"
- **Trigger:** `gstin 27AAPFU0939F1ZV`, or any 15-character string matching
  `^\d{2}[A-Z]{5}\d{4}[A-Z][1-9A-Z]Z[0-9A-Z]$` on paste. Also `pan ABCDE1234F`,
  `aadhaar <12 digits>` (Verhoeff checksum, first digit 2 to 9), `ifsc SBIN0001234`
  (4 letters, `0`, 6 alphanumerics; bank name from a bundled bank-code table).
- **Return copies** `Valid, Maharashtra, PAN AAPFU0939F (Firm)`. Aadhaar,
  PAN and IFSC checks opt out of History.
- **GSTIN rules:** positions 1 to 2 state code (table: 01 to 38, 97 other
  territory, 99 centre jurisdiction); 3 to 12 the PAN, whose 4th character gives
  entity type (P person, C company, H HUF, F firm, A AOP, T trust, B BOI, L local
  authority, J artificial person, G government); 13 the registration count for
  that PAN in the state (1 to 9, then A to Z); 14 is `Z`; 15 is the checksum.
- **Checksum (offline):** map characters to base 36 (`0-9` then `A-Z`). For each of the
  first 14 characters multiply its value by 1 (odd positions) or 2 (even), add
  `product div 36` and `product mod 36` to a running sum, and the check character
  is the base 36 symbol of `(36 - sum mod 36) mod 36`. Test vectors are
  synthesised by running the algorithm, not copied from real registrations.
- **On failure:** says what failed (length, state code, PAN shape, checksum) and
  suggests corrections that make the checksum pass: one wrong character, or two
  swapped adjacent characters, listed as chips.
- **Honest limit:** the check proves shape and checksum, **not** that the number
  is registered or active. Status lookup needs the GST portal (captcha, no
  public API for individuals) so it is not offered; the card links the official
  search page.
- **Quality bar:** 100% agreement with an independent implementation of the algorithm
  on 100,000 generated values and on a set of user-supplied real numbers
  (checked locally, never uploaded). Beat web validators on offline and typo hints.
- **Surfaces:** bar, invoice client field, CLI `panoply in gstin`, MCP `in_gstin_check`.
- **Budgets:** Under 1 ms. The checksum is 15 integer operations; typo
  suggestions try at most a few hundred candidates, still under 1 ms. State
  table and bank-code table are a few KB, compiled in.

### 15.3f UPI QR

- **Pattern:** E. **Job:** "A QR customers can scan to pay me, with the amount filled in."
- **Inputs:** UPI ID (VPA), payee name, optional amount, note, reference, merchant
  code. Pre-fills from the profile. Reads an existing QR image to import a VPA.
- **Payload (NPCI UPI linking spec):**
  `upi://pay?pa=<vpa>&pn=<name>&am=<amount>&cu=INR&tn=<note>&tr=<ref>&mc=<mcc>`.
  `pa` and `pn` are required; `am` is optional with at most 2 decimals; `cu` is
  `INR`; every value is percent-encoded (`%20` for a space, never `+`).
- **Validation:** VPA shape `handle@psp` (letters, digits, `.`, `-`, `_`, then
  `@` and letters); it cannot be checked for existence offline, and the card says so. Notes
  are kept short with a warning because apps truncate; `pn` is a hint, since payment
  apps show the registered account name.
- **Output:** PNG, SVG and PDF, error correction M (Q with a logo), quiet zone
  per the QR standard, printed size warned below 2 cm square. A table-tent and a
  counter-card layout in print sizes. On invoices (15.1) it is dynamic: the
  amount and invoice number go in `am` and `tr`.
- **Edge cases:** an amount in the QR that a customer can edit in some apps (the
  card says to check the received amount); personal VPAs used for business
  (the card suggests a merchant VPA from the bank); bank-issued static merchant
  QRs use the EMVCo (BHARAT QR) payload, which we read but do not re-issue.
- **Quality bar:** the generated QR is scanned and parsed back by three
  independent decoders in CI, and a manual checklist scans it in at least three UPI
  apps before each release, since pre-fill behaviour differs by app. Beat
  bank-app QR screens on amount-filled, printable and offline use.
- **Surfaces:** panel, invoice flow, bar (`upi name@bank 500`), CLI `panoply in upi-qr`, MCP `in_upi_qr`.
- **Budgets:** QR render under 10 ms for the screen preview (SVG), print-size
  PNG under 50 ms. No resident state.

## 16.1 Photo print sheets

## 16.2 Poster tiling

## 16.3 Booklet

- **Pattern:** A. **Job:** "Reorder these pages so I can print, fold and staple a booklet."
- **Inputs:** one PDF.
- **Imposition:** pads the page count to a multiple of 4 (blanks at the end by
  default, or a chosen position). For N = 4m pages, sheet i front is
  `[N - 2(i - 1), 2i - 1]` and its back is `[2i, N - 2i + 1]`: 8 pages give
  `8|1, 2|7, 6|3, 4|5`. Pages are scaled onto landscape sheets (A5 on A4, half
  Letter).
- **Options:** binding edge (left, or right for Arabic, Urdu, Hebrew and
  Japanese vertical), gutter, creep compensation for thick booklets
  (paper thickness and sheet count), signatures of 16 pages for stitched
  binding, duplex flip set in the PDF (`/Duplex /DuplexFlipShortEdge`).
- **Edge cases:** mixed page sizes (normalized with a warning); pages with
  their own rotation; PDFs with forms and annotations flattened only if
  asked; printers that ignore the duplex hint (the sheet states "flip on short
  edge" in a margin note on the first sheet).
- **Quality bar:** page order equals `pdfbook2` and Acrobat's booklet mode on a
  test set from 4 to 200 pages, verified by extracting page numbers from a
  numbered test PDF. Beat macOS Preview (no booklet) and printer drivers on
  creep and RTL.
- **Surfaces:** right-click on PDFs, CLI `panoply print booklet`, MCP `print_booklet`.
- **Budgets:** Page reordering is a PDF page-tree rewrite: no re-rendering,

  second and the output is roughly the input size. Memory under 100 MB, since
  pages are referenced not decoded.

# 17. Your computer

Later phase, desktop first. These are the modules most tied to operating
system internals, so every spec starts with a feasibility line. Marks: **Y**
public API, **P** needs a user permission, **X** private or undocumented API or
privileged helper, **N** impossible. "Phone" means iOS and Android. None of these
can run in the phone app except where stated. Every module here that changes
system state shows what it will change before doing it and can undo it.

## 17.1 Window snapping

- **Pattern:** G. **Job:** "Snap this window to a half, third or corner with a shortcut."
- **Feasibility:** macOS **P** (Accessibility API, `AXUIElement`); Windows **Y**
  (`SetWindowPos`); Linux X11 **Y** (EWMH), Wayland **N** in general (a client
  may not move other clients' windows; only compositor extensions such as a KWin
  script or GNOME extension can); phone **N**.
- **What it does:** halves, thirds, quarters, maximize, center, restore, move to
  next display, with a shortcut each and optional drag-to-edge. Custom zones
  are phase 2.
- **Edge cases:** windows with a minimum size (snap as close as possible, say
  so); multiple displays of different scale; full-screen and Stage Manager
  spaces; macOS 15 and later has its own tiling (coexist, do not fight it);
  elevated windows on Windows cannot be moved from a normal process.
- **Quality bar:** placement within one frame (target under 100 ms) and
  pixel-exact across displays. Beat Rectangle (the open-source bar, equal
  action coverage), Magnet and Moom on being included, and PowerToys
  FancyZones on custom zones once added.
- **Surfaces:** global shortcuts, bar (`snap left`), CLI `panoply sys window snap left`.
- **Budgets:** Always on, event driven: it registers global shortcuts and does
  nothing else, zero wake-ups when idle. Resident under 10 MB. Placement is
  one OS call per window and finishes within a frame (target under 16 ms in
  the module, under 100 ms end to end).

## 17.2 Keep awake

- **Pattern:** G. **Job:** "Do not sleep while this runs."
- **Feasibility:** macOS **Y** (IOKit power assertions, like `caffeinate`), Windows
  **Y** (`SetThreadExecutionState`), Linux **Y** (logind and
  `org.freedesktop.ScreenSaver` inhibit over D-Bus), iOS **Y** while the app is
  in front (`isIdleTimerDisabled`), Android **Y** (wake lock or keep-screen-on).
  Keeping a Mac awake with the lid closed is **X** (needs a helper and power
  settings) and is not offered.
- **Options:** duration (indefinite, 30 min, 1 h, until a time), keep the display on
  or allow it to sleep, stop below a battery level, stop on battery, while a named
  app runs.
- **Edge cases:** battery drain warning on battery power; the system overriding
  with thermal or low battery sleep; never simulates mouse or keyboard input
  (it holds a power assertion, nothing more).
- **Quality bar:** the assertion releases on quit and on crash (OS-held, tested
  by killing the process). Beat Amphetamine, Caffeine and PowerToys Awake on
  conditions (while an app runs, below a battery level) in one small tray item.
- **Surfaces:** menu bar or tray, bar (`awake 2h`), CLI `panoply sys awake 2h`, MCP `awake_start`.
- **Budgets:** Holds one OS power assertion and does nothing: zero CPU and
  zero wake-ups, so it never causes the battery drain it prevents. Conditions
  (app running, battery level) are OS notifications, not polling. Resident
  under 5 MB.

## 17.3 App uninstaller

- **Pattern:** I with fix. **Job:** "Remove this app and all its leftovers."
- **Feasibility:** macOS **P** (Full Disk Access to see all leftovers and App
  Management permission to remove other apps' bundles on macOS 13+); Windows
  **P** (elevation for machine-wide installs) through the app's registered
  uninstaller and `PackageManager` for Store apps; Linux **Y** through the package
  manager (apt, dnf, pacman, Flatpak, Snap) with `pkexec` for root; phone **N**
  (iOS cannot remove other apps, Android only shows the system confirmation).
- **Flow:** drop an app or pick one; the report lists the bundle and exact-ID
  leftovers (macOS: `Application Support`, `Caches`, `Preferences`,
  `Containers`, `Group Containers`, `Saved Application State`, `LaunchAgents`,
  `Logs`; Windows: `AppData`, `ProgramData`; Linux: `~/.config`, `~/.local/share`,
  `~/.cache`, Flatpak data) with sizes. Exact bundle-ID matches are pre-checked;
  name-guessed matches are shown unchecked.
- **Safety:** everything goes to the Trash, never `rm`; Windows registry cleaning
  is not offered (only the app's own uninstall entry is touched); system apps
  are refused; a "Reset app" mode deletes data and keeps the app.
- **Quality bar:** after uninstall of 30 test apps, no exact-ID leftovers remain
  and nothing outside the report was removed (a before and after file listing diff).
  Beat AppCleaner (macOS), Bulk Crap Uninstaller (Windows) and Revo on safety
  defaults.
- **Surfaces:** drop on bar, right-click, CLI `panoply sys uninstall`, MCP `app_uninstall_plan` (plan only, never executes).
- **Budgets:** Leftover scan only reads directory names and sizes under known
  folders (no full-disk walk), finishing under 2 s typically and cancellable.
  Memory under 100 MB. Nothing runs after the report is closed.

## 17.4 Disk cleanup

- **Pattern:** I with fix. **Job:** "Free space safely."
- **Feasibility:** macOS **P** (Full Disk Access for some areas), local Time Machine
  snapshots need `tmutil` with admin (**P**); Windows **P** (component cleanup
  needs admin); Linux **Y** (package caches via the manager, journal vacuum);
  iOS **N**; Android **N** beyond the app's own space.
- **Categories (in three tiers):** *Regenerates* (user caches, logs, browser
  caches, package-manager caches such as npm, pip, cargo, Homebrew, Xcode
  DerivedData and unavailable simulators, Docker prune after a `df` summary);
  *Review* (old installers in Downloads, old iOS backups, mail attachments,
  stale `node_modules`, `target` and `.venv` of projects untouched for N days);
  *Never touched* (system files, documents).
- **Flow:** scan with sizes, nothing selected for Review items, Run shows the
  exact paths first. Recoverable items go to Trash; regenerating caches are
  deleted and the card says they will be rebuilt.
- **Edge cases:** a cache in use (skipped); a dev cache that costs a long rebuild
  (flagged with the cost); network drives; huge trees (progress, cancel).
- **Quality bar:** after a run, the 20 reference apps still launch and a
  reference project builds. Beat BleachBit on safety defaults and dev artifacts,
  macOS Storage Management and Windows Storage Sense on dev tools and a dry
  run. This overlaps Find in section 7 (big files, duplicates); cleanup links to
  those rather than reimplementing them.
- **Surfaces:** panel, CLI `panoply sys clean --dry-run`, MCP `disk_clean_plan` (plan only).
- **Budgets:** Scan is a bounded parallel walk (4 threads) of known cleanup
  locations and project roots; progress shown after 300 ms, cancel instant.
  Sizes are summed incrementally with constant memory regardless of tree size.
  No background scanning: runs only when opened.

## 17.5 Battery health

- **Pattern:** I. **Job:** "How worn is my battery?"
- **Feasibility:** macOS **Y** for level and charging, health percentage and cycle
  count come from IORegistry `AppleSmartBattery` keys that are **X** (undocumented
  but long stable and read-only; coconutBattery uses them); Windows **Y** (WMI
  `BatteryStaticData` and `BatteryFullChargedCapacity`; cycle count where the
  firmware reports it); Linux **Y** (`/sys/class/power_supply`, UPower); iOS
  **N** (no battery health or cycle API); Android **P**/partial (recent versions
  expose cycle count, health percentage is not generally available).
- **Shows:** design versus current full capacity as a percentage, cycle count,
  temperature, power adapter wattage, a daily local snapshot that draws a
  degradation chart. Charge limiting needs an SMC write through a privileged helper
  (**X**) and is not part of this module.
- **Edge cases:** desktops without a battery (module hidden); a battery just
  replaced (capacity can exceed design); Apple Silicon versus Intel reporting
  differences; unavailable data shown as "not reported", never a guess.
- **Quality bar:** matches coconutBattery and `powercfg /batteryreport` within
  one percentage point on test machines. Beat both on a trend chart and on
  appearing in the bar.
- **Surfaces:** bar (`battery`), CLI `panoply sys battery`, MCP `battery_status` (read only).
- **Budgets:** One IORegistry, WMI or sysfs read under 20 ms, on demand. The
  daily snapshot is a single 16-byte record written by one scheduled OS job (a
  LaunchAgent or scheduled task) that runs for under 100 ms and exits, so
  there is no resident process for it.

## 17.6 System monitor

- **Pattern:** I, live. **Job:** "What is eating my CPU, memory, disk and network?"
- **Feasibility:** macOS **Y** for CPU, memory, disk, network and same-user
  processes (`mach` and `libproc`), GPU utilization via IOKit accelerator stats **Y**,
  temperatures and fans **X** (SMC and private HID sensors, or `powermetrics`
  as root); Windows **Y** (PDH counters, GPU engine counters), temperatures
  **X** (need vendor drivers or a kernel driver such as LibreHardwareMonitor,
  admin); Linux **Y** (`/proc`, `/sys/class/hwmon`, NVML for NVIDIA); phone
  **N** (iOS has no per-process view, Android limited to the app's own).
- **Shows:** menu bar sparkline, popover with per-process CPU, memory, disk and
  network, and one-click quit or force quit with a confirmation. Other users'
  processes need admin and are shown as aggregates.
- **Edge cases:** processes that exit between samples; per-core versus total
  percentages (setting); memory pressure versus "used" (macOS shows pressure, not
  the misleading used number); sleep and wake gaps.
- **Quality bar:** CPU and memory per process within 2 percentage points of Activity
  Monitor and Task Manager on a stress test. Beat Activity Monitor on menu bar
  visibility and iStat Menus on being free, and Stats (open source, macOS) on
  cross-platform. Use the `sysinfo` crate as the base.
- **Surfaces:** menu bar, panel, CLI `panoply sys top`, MCP `system_stats` (read only).
- **Budgets:** The exception that stays cheap by design: samples only while
  the popover or menu bar graph is visible, once a second, and the sampler
  itself uses under 0.5% of one core and under 25 MB resident. With the graph
  hidden, zero wake-ups. Sampling reads counters in bulk (one
  `host_processor_info`-class call), not per process polling, and the
  sparkline is drawn by the GPU at 120 fps. A monitor that shows up in its own
  top-process list is a bug.

## 17.7 Per-app volume

- **Pattern:** G. **Job:** "Make this app quieter than that one."
- **Feasibility:** macOS **X**, and hard: it needs a virtual audio driver (an
  Audio Server plug-in, installed with admin and notarized) or Core Audio process
  taps (macOS 14.2 and later) with re-rendering through an aggregate device;
  Windows **Y** (`ISimpleAudioVolume` per audio session) but the built-in volume
  mixer already does this; Linux **Y** (PipeWire and PulseAudio per-stream volume)
  and every mixer already does this; phone **N**.
- **Verdict:** only macOS has real value, and it is the costly one. **Recommend
  cutting from the first release** (see summary). If built: a per-app slider,
  per-app output device, remember levels by app, bypass when the driver fails.
- **Quality bar if built:** added latency under 20 ms and no audible glitches in a
  one-hour test. The bar to beat is SoundSource (paid), which owns the driver.
- **Surfaces:** menu bar, CLI `panoply sys volume --app Spotify 40`.
- **Budgets:** If built: audio stays real time. The driver or tap adds under
  20 ms latency and under 1% of one core while audio plays, zero when no app
  is playing. This and the permission and driver cost are why it is
  recommended for deferral.

## 17.8 Keyboard remapping

- **Pattern:** G. **Job:** "Caps Lock to Escape, swap two keys, add a shortcut."
- **Feasibility:** macOS simple key-to-key remaps **Y** through `hidutil`
  (no permission, does not survive reboot unless a login item re-applies it);
  tap-hold, layers and per-app rules are **P** (event tap needs Input Monitoring
  and Accessibility) or **X** (Karabiner's DriverKit virtual device). Windows
  simple remaps **Y** via the Scancode Map registry value (admin, reboot) and richer
  ones **Y** via a low-level hook (PowerToys Keyboard Manager's route; cannot act
  in elevated windows without elevation); Linux **P** (evdev and uinput need the `input`
  group; works on X11 and Wayland, as keyd and kmonad do); phone **N**.
- **Scope for v1:** key-to-key, key to shortcut, shortcut to shortcut, Caps Lock
  tap Escape and hold Control. Per-app rules second. Layers and macros later.
- **Safety:** an always-available escape: hold both Shift keys for 5 seconds to
  disable all remaps; a remap set that breaks typing is auto-reverted after a
  15 second "keep this change?" prompt.
- **Quality bar:** adds no measurable input latency (target under 1 ms per event),
  no stuck modifiers after sleep or fast user switching. Beat PowerToys Keyboard
  Manager on macOS and Linux coverage, Karabiner on setup and not needing a
  driver for simple remaps.
- **Surfaces:** panel, CLI `panoply sys keys`.
- **Budgets:** Always on, so held to the strictest number: zero wake-ups when
  no key is pressed, under 1 ms added per key event, and a 5 MB resident cap.
  The hook callback only looks up a table (no allocation, no I/O). Simple
  remaps via `hidutil` or the Scancode Map hold nothing in memory at all,
  since the OS does the work.

## 17.9 Hosts file editor

- **Pattern:** C. **Job:** "Edit hosts entries safely, with profiles."
- **Feasibility:** macOS **P** (root-owned file; a one-time privileged helper, or an
  admin prompt per save), Windows **P** (UAC elevation; Windows Security can
  flag hosts entries that block security-vendor domains), Linux **P** (`pkexec`);
  phone **N** (iOS no; Android needs root or a VPN-based DNS).
- **Features:** toggle entries on and off, comments, profiles (work, dev, blocklist)
  switched in one click, syntax and duplicate validation, search, import a
  blocklist file, a backup written before every save and a one-click restore.
  After saving: flush the DNS cache (`dscacheutil` and `mDNSResponder` on macOS,
  `ipconfig /flushdns`, `resolvectl flush-caches`).
- **Edge cases:** CRLF and BOM preserved; a 100,000-line blocklist (virtualized
  list, fast toggle); IPv6 entries; the file edited by another tool between
  open and save (detect, three-way merge or refuse).
- **Quality bar:** never produces an invalid file, and restore returns the
  original byte for byte. Beat PowerToys Hosts File Editor (Windows only) and
  Gas Mask and SwitchHosts on being cross-platform with backups.
- **Surfaces:** panel, CLI `panoply sys hosts list|add|enable`, MCP `hosts_list` (read only; edits ask the user).
- **Budgets:** Opens under 50 ms; the file is read once and edited in a
  virtualized list, so a 100,000-line blocklist scrolls at 120 fps and uses
  under 50 MB. Saves are atomic. Nothing runs after close.

## 17.11 Cleaning mode

- **Pattern:** A, timed. **Job:** "Lock the keyboard and trackpad so I can wipe them."
- **Feasibility:** macOS **P** (an event tap that swallows key and pointer events
  needs Accessibility and Input Monitoring; the power button cannot be blocked);
  Windows **P** (a low-level hook that swallows input; `BlockInput` needs admin
  and Ctrl+Alt+Del bypasses it); Linux X11 **Y** (grab), Wayland **N** in
  general (evdev grab needs the `input` group); phone: screen touch lock only
  (a black screen with hold-to-exit; iOS already has Guided Access, and hardware
  buttons cannot be blocked).
- **Flow:** one click starts, the screen goes dark with a countdown (default 60
  seconds, max 5 minutes), and the exit is a long hold of the mouse button or
  a chosen key chord that the tap lets through. A watchdog releases input if the
  app hangs, and an event tap dies with the process, so a crash unlocks.
- **Edge cases:** external keyboards and mice (also locked, optional); the lid
  closing; the Touch Bar; sleeping during the lock.
- **Quality bar:** never traps the user: tested with a forced kill and a hung
  UI thread. Beat KeyboardCleanTool on timer, display dimming and the dead-man
  release.
- **Surfaces:** bar (`clean mode`), CLI `panoply sys lock-input 60`.
- **Budgets:** Zero cost until started. While active it swallows events (a
  callback under 50 microseconds) and draws one dark view with a countdown
  that repaints once a second. Resident under 10 MB for those seconds, nothing
  after.

## 17.12 Raycast extension compatibility

- **Pattern:** n/a (a runtime, not a module). **Job:** "Run the Raycast extensions I already use."
- **Feasibility:** **possible only as a best-effort subset.** Raycast extensions are
  React and TypeScript apps that call the `@raycast/api` package (List, Detail,
  Form, Action, and system calls); the host implementation is closed. Compat
  means re-implementing that API surface in Panoply's UI and running extensions
  in a Node or Bun sidecar, as Vicinae (open source, Linux) already attempts
  (verify its current state). Many extensions call macOS-only things (AppleScript,
  Swift, `run-applescript`, `Application`/Finder APIs) and cannot work on
  Windows or Linux; those are marked unsupported, not faked. Phone **N**.
- **Legal and policy gate:** the extension repository is MIT licensed, but the Store
  download service and branding terms must be read, and a legal review is needed
  before shipping. Extensions read local data and can run shell commands, so each
  one declares permissions in a prompt on install, and Panoply adds a
  network allowlist and a "no shell by default" mode.
- **Scope:** import the top N pure-TypeScript extensions by installs first,
  report a compatibility score per extension in the app, never silent failures.
- **Quality bar:** a published compat matrix per extension and API; each
  supported extension runs a smoke test in CI. This is the highest-effort item in the
  section; ship it as an experiment behind a switch.
- **Surfaces:** bar results, CLI `panoply ext run <name>`.
- **Budgets:** The heaviest item by design and the main exception to the
  table. A Node or Bun sidecar and React rendering cost real memory (target
  under 150 MB with one extension active, and the sidecar starts only when an
  extension is invoked and exits 60 s after the last use, matching the model
  unload rule). Extension start under 300 ms warm, and results that stream in
  must not block the bar's 120 fps. Extensions that cannot meet this are
  marked in the compat matrix. Ships behind a switch for this reason.

# Policy notes

## Internet by nature (opt-in, clearly labelled)

The default build makes no network requests. A module that needs the network
must declare it in its manifest, and the rest follows from that.

- **Declaration.** Each networked module lists hosts, method, and exact payload
  fields in its manifest. A `network-manifest` page in Settings lists every
  declared host for the whole app in plain words, so a reader can audit it.
- **Opt-in.** Each networked module is off until switched on. The first use
  shows the Privacy line: where the request goes, what is sent, what comes back.
  Examples: Currency (12.3) fetches one static file a day from the Panoply
  mirror and sends nothing about the user; Password breach check (14.4) sends
  5 hex characters of a SHA-1 hash to the HIBP range endpoint; DNS and domain
  (13.17) sends the queried domain to the chosen resolver and, for RDAP, to the
  registry; token counting in exact mode (13.16) sends the text to the model
  provider with the user's own key.
- **No accounts, no keys of ours, no analytics.** A key the user supplies stays
  in the OS keystore and is never logged.
- **One gateway and an airplane switch.** All requests go through a single host
  function (no module opens its own sockets), so one switch turns the network off
  and a log shows each request made in the session. A module that works offline
  caches its last good data and keeps working.
- **Out of the default build:** media saving from websites ("YouTube to MP3",
  about 2.2M searches a month in the US) stays a community module, desktop
  only, outside the app store builds, because of platform terms and legal
  risk. It is not specified here and not promised.
- **Related actions that cross the line even inside offline modules:** fetching a
  site's certificate (13.15), looking up a public IP (13.13), VAT ID checks against
  VIES (15.1), JWKS download (13.3, never done automatically). Each is a separate
  labelled action.

## Model downloads

🧠 modules download their model once, on first use, from the Panoply release
mirror. After that they never touch the network.

- **Before the download:** the card names the model, its size from the manifest,
  its license, and the module it serves. The user confirms, can pause and resume,
  and can pick a smaller option where one exists (for example per language pair in
  11.9). Downloads are over HTTPS and verified against a hash and signature in the
  signed release manifest; a failed hash deletes the file.
- **Storage:** one models folder, with a size readout, a per-model Delete, and a
  "free all" button. Models are shared between modules (the names and IDs model serves
  11.3, 14.2 and "Mask ID numbers").
- **Metadata:** every model ships a `MODEL.json` (name, version, license,
  source URL, weights hash, training data note). A model with a non-commercial
  or unclear license is not shipped. This file's modules use: a small
  token-classification model for names and addresses (11.3, 14.2), translation
  models per pair (11.9), plus the OCR, face and speech models owned by other
  sections.
- **Offline behavior:** a module whose model is not yet downloaded and has no
  network says exactly that and keeps working in its non-model mode where one
  exists (11.3 still redacts by regex and checksum, 14.2 still finds IDs).
- **Never:** no model runs on the network, and no text, file or telemetry is sent
  to the mirror.
