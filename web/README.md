# Panoply on the web

The tools of the desktop app, running in the browser at `panoply.anzalabidi.dev/tools/`. Files are never uploaded: every tool runs on the
visitor's device. This folder is the source; the site (`site/`) builds it into `site/public/tools/` and wraps each tool in an indexable page.

## What is in here

| path | what |
|---|---|
| `app/` | the JavaScript: a small shared shell (`src/shell.js`), one module per tool (`src/tools/`), the workers, and the build (`build.mjs`) |
| `app/src/*wasm/` | the compiled engines (wasm-bindgen output, checked in so the site builds with Node alone) |
| `crates/pdf` | page building, merge, split, organize, compress, searchable PDF, pictures to PDF: the desktop `panoply-pdf` engine |
| `crates/panoply-pdf-web` | a fork of `crates/panoply-pdf` with three `cfg(target_arch = "wasm32")` stubs for its native-only pdfium and file calls; the page-building code is unchanged |
| `crates/vision` | background removal, erase and watermark detection: the desktop pre and post processing around the model runs |
| `crates/ocr` | the PP-OCRv5 pipeline around the model runs |
| `crates/id` | passport photo, signature cleaner, print sheet, with the desktop resampler |
| `crates/media` | the BS.1770 loudness meter and the gain planning |


Models are the same pinned files the desktop downloads (URL and SHA-256 are in `app/src/ai/models.js`), fetched by the browser on first use and kept
in Cache Storage. The Real-ESRGAN files come from a host without CORS headers, so `build.mjs` fetches them at build time and the site serves them.

## Build

```sh
cd web/app && npm ci
cd ../../site && npm ci && npm run build      # builds the tools into public/tools/app, then the site
```

Rebuilding the wasm needs Rust with the `wasm32-unknown-unknown` target, wasm-bindgen and binaryen, and is only needed when a crate changes:

```sh
cd web && cargo build --release --target wasm32-unknown-unknown
# then for each crate: wasm-bindgen --target web --no-typescript --out-dir app/src/<name>wasm <the .wasm>; wasm-opt -O3 (see app/wasm.sh)
```

## Threads without custom headers

GitHub Pages cannot send `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy`, which `SharedArrayBuffer` needs. `site/public/tools/sw.js`
(generated by `app/build.mjs`) is a service worker for `/tools/` that adds both headers to the responses it serves. Each tool page registers it and
reloads once. With threads, ONNX Runtime Web runs four threads; without them (a browser that blocks service workers, or private modes) every tool
still runs, single-threaded. The same worker caches the app files for offline use.

## Scripts (`app/scripts/`)

- `live.mjs`: the service worker must isolate the page after one reload, and not when blocked.
- `smoke.mjs`: runs every tool once, with and without the worker.
- `threads.mjs`: times the ONNX tools with and without threads.
- `shots.mjs`: breakpoint pass (375 to 2560), console errors, failed requests, sideways overflow and axe on every page.
